# PR99 有效数据绑定与原控制器接线增量

这是新源码候选，不是已安装的生产控制器，也不签发迁移许可。
原40文件候选未重发，原生产入口仍HOLD，原M99动态入口未运行。

- `catalogue_binding.py` 将三应用的有效配置证据明确关联数据对象、写入者和激活源；验证完整目录成员、共享保留对象以及证据的准确哈希。源码默认值、空FD采样、初始环境均不能替代有效配置与覆盖证明。
- `existing_fd_controller.py` 借用原Journal、原锁和持有目录fd；禁止新建控制器目录、claim、Writer或epoch。新接线源码集合也必须绑定准入。既有INTENT只查询；UNKNOWN不重发、不自动继续。
- `stage_history.py` 对已发布原事件格式新增纯阶段顺序/前序回执/失败收敛校验；未复制未发布40文件中的history实现。作者不能将新校验器自行视为已独审。
- `source_fence.py` 提供固定systemd与内核文件标志接口，仅在完整有效清单和真实排空证明均获准后使用。保留服务冲突、cgroup缺口、内核能力不足或部分执行全部HOLD，不尝试替代接口。没有自动解冻或东京恢复入口。
- `held_proof.py` 只向原已独占持有的输出fd写一次证明；查询不创建证明，部分记录不覆盖。

## 测试边界

107项普通临时目录/状态夹具/系统接口mock测试，不运行原PathGuard或M99目录替换反例，不执行systemctl或真实不可变标志ioctl，不打开生产数据库。跨进程测试重新取得同一原账本锁并只查询既有INTENT。fixture的授权/路径/排空回调不是现场可信签发方。

## 尚未解除的两项实机缺口

1. 尚无完整有效配置到权威数据的现场签认清单；全部闲置、手动、调度、共享写入源覆盖尚未证明。本候选验证清单但不伪造/采集出不存在的授权覆盖证明。
2. 尚未在获准环境接入原受信控制器、原PathGuard及真实排空源，也没有内核Fence、非空WAL完整捕获、实机恢复与独审证据。原发布拒绝原文/正常解除及M99获准动态入口仍属独立依赖。

这些现场条件没有被86项普通测试关闭。不得把新代码存在理解为已领取生产Writer、已Fence、已安装或可停止东京。后续原独审应准确绑定本新增源码、原未变依赖、完整现场清单和最多5次正式Attempt许可；未取得前不触发生产。


## 本次接线入口

`capture_session.CaptureSession.perform(request)` 将原ExistingFdController的INTENT/RESULT链、真实排空依赖、SourceFence与HeldProof、已发布node_bindings的非空WAL输出连在一起。final_snapshot只能使用原账本中成功的Fence回执，并重新核对当前Fence与原证明；捕获输入合同绑定到原plan，避免预先要求尚未生成的Fence哈希。原已通过WAL算法未改。

SQLITE工作项明确绑定MAIN/WAL/SHM成员与schema，普通FILE工作项使用原guard创建的独占fd；全部COPY_FENCED文件必须归入工作项，缺项/重复/交叉源目标均拒绝。源guard、原持有证明fd、cgroup绑定、排空证据均是原受信现场提供的依赖，不使用fixture代替。内核Fence只允许固定东京root身份。既有INTENT进入查询时仅核对已有输出/原始捕获/证明，不重跑SQLite、不新建捕获输出、不重设Fence；不完整状态保持UNKNOWN。

新增12项测试（含固定源主机接口拒绝）使总数57；受影响45项也重新验证。新增调用链测试真实使用已发布的SQLite内存VFS，非空WAL内17行提交能恢复到候选输出，同时复制普通状态文件，并测试部分输出、输入/代码/准入变化与只查恢复。这些仍是普通合成夹具，不是生产数据或M99。当时只接通fence_source、final_snapshot；不宣称其后的传输、canonical assignment、安装与切换已落地，也不输出FINAL_CANONICAL_CHECKPOINT。

## 排空入口封闭绑定修正

空队列采样不再足以进入Fence。原真实排空源必须同时确认持久入口封闭，列出本次数据对象关联的全部原写入/激活来源，并绑定原事务、plan、inventory、epoch与原plan内有效期。每次mask、stop、freeze前重新校验同一份封闭记录；记录失效/变化、来源缺口或再次出现待处理/未知项均立即HOLD，保留已有部分效果，查询不重复执行。新增8个反例测试，总数65。

这次修正实现的是原排空源到Fence的严格接线，**没有实现或部署现网应用的入口封闭接口**，也没有把mock回调当作真实队列排空。原受信现场必须提供能实际封闭并持续证明封闭的机制；缺少则不能启用本候选。

## 应用侧入口封闭/排空组件（未部署）

`ingress_gate.ApplicationIngressGate` 不再只检查外部布尔值：它实际拥有有界普通任务队列，`submit`在登记后接收任务；`process_one`将已接任务执行一次；`run_sync`覆盖同步事务直到处理器返回。`seal`在同一互斥区内封闭新入口并向原预持有的一次性fd保存封闭记录；封闭后原已接任务仍能完成。`query`/`wait_drained`观察真实已接、活动与异常任务，等待不超过60秒。回调返回前必须已完成commit/rollback且没有脱离跟踪的后台写入，原覆盖核查必须确认这一点。

异常、处理器返回后准入失效均保存UNKNOWN；`reconcile_unknown`只接原任务的已提交/无效果终态证明，不调用任务第二次。容量、队列直接注入、原fd更换/部分写入/封闭记录更改及第二对象/进程竞争均拒绝。原fd上的flock仅是应用入口封闭记录的独占借用，不创建新文件、迁移锁、Journal、Writer、epoch或发行人；原持有方保留fd生命周期。

封闭记录绑定原事务/plan/inventory/epoch、来源、内核主机/PID/start_ticks/boot摘要及唯一gate实例。重建同进程对象或启动新进程即使队列为空，也返回UNKNOWN_PRIOR_PROCESS，绝不自行清除旧封闭记录或宣称已排空。原启动对账证明缺失时也不能认证排空。它不是持久任务队列，不恢复或重发丢失的工作。

新增21项普通本地真实queue/thread/fd/flock/跨进程测试（无systemctl/生产库/M99），合计86项。原控制器的extension manifest绑定该新增源码，制品包含新组件与测试。

**仍缺现场接入**：三个原应用的同步写入与异步队列尚未全部改为调用本组件；未安装任何新控制端点，未把单进程观察当成全部origin覆盖。此组件的输出不是SourceFence的可信全局排空证明；原受信端仍须绑定各进程/调度/共享来源、完整清单与原控制通道，汇集核验后才可提供原SourceFence要求的证明。本轮不激活生产、不停止东京，不声称第二实机门禁关闭。

应用必须传入原任务ID：`submit(original_job_id,payload)`、`run_sync(original_job_id,handler,...)`，UNKNOWN对账使用同一ID，绝不另造迁移任务或重新发起原效果。当前进程已接收ID不重复执行，已接收历史最多65536个，不驱逐记录来重置额度；它仍不替代原应用的跨进程持久幂等记录。


## 最终目标核对与原Writer交接接线（未部署）

`final_handoff.OriginalSourceEvidence`从原认证只读源端查询核验准确的Fence/捕获回执和原账本结果；源fd仍在东京，目标fd仍在国内，不假设跨主机可以传递或同时使用本地fd。原source-query适配及其信任核验是现场依赖，不由新组件伪造。

`FinalHandoff.perform`只开放`reconcile_final`及`assign_writer`，沿原Journal/锁/epoch，INTENT先于效果。目标已由原传输收齐的完整文件/链接清单、预持有fd身份/属主/权限/实际字节，逐项绑定原捕获工作项和固定源码摘要；全部WAL恢复输出及普通数据项必须被覆盖。核对后在原持有输出fd写入正式启动器可读取的最终检查点。Writer交接必须调用原权威方的实际CAS，并由其核验持久结果；仅生成JSON或返回成功布尔值不能冒充交接。

已有INTENT只走原query，不能重新捕获/恢复SQLite或重发Writer CAS；原CAS已执行但本地证明缺失时保留UNKNOWN，不在查询中补写证明。初步R2目标、额外文件/错误链接、目标fd变更、输入变更、未认证源查询与原生结果未知均拒绝。没有启动服务/修改路由/新建Writer或账本。

原HeldProof的16KiB默认容量保留；捕获清单及最终检查点显式采用最多2MiB，防止正常文件清单超过16KiB后无法交付。超界/部分写入仍保留，不覆盖。

新增21项普通合成测试，共107项；复用实际非空WAL合成恢复、普通目标文件及fd、原账本和证明字节，并用已发布正式启动校验器验证最终格式兼容。目标UID/GID、原生Fence与赋权均是明确的fixture/mock，不是生产信任或M99；没有发主机命令。
