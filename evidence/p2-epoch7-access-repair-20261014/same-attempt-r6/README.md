# P2 same-attempt r6 continuation capture

FEATURE_ID: P2_RETAINED_RECOVERY

This separately authenticated wrapper invokes the unchanged published r6 continuation exactly once. The normal continuation authenticates its existing kit, checks the completed r3 receipt and current three 0755 directories, writes a fresh full observation, and runs the already scoped finite probe only if its original gates pass. No permission repair, UID fixture, preparation, production activation or resume is replayed.

## Same-invocation evidence

The wrapper authenticates the existing failed r6 observation and diagnostic receipt, then uses fresh random identifiers supplied by its bootstrap. Those previous files establish continuity only. It downloads the exact r6 outer source from commit 3199565b2f0d91d788251a7d52e6b749937b991d, checks its 27,133-byte size and SHA256, and invokes its original run function once.

A temporary profile hook authenticates the actual staged kit and CachedSources loader, acquires the actual imported function code objects, and binds one observe_host / observe_with_io / collect backend and frame lineage. It records the original comparison inputs by identity without replacing functions, returned objects or the safety comparison. At most two original writer calls and two original process scans are captured. Bounded same-call stat/comm observations supply diagnostic PID/starttime/UID/kernel-thread/FD-count attribution. No extra process reads are added.

The hook is removed before any finite probe. An uncertain disarm cannot proceed into the probe. Original exceptions and failure status are preserved. Ordinary capture failures are UNKNOWN and do not change the underlying collector result. The supplemental terminal JSON includes the original result and any genuinely available receipt/observation hashes; it does not alter the original 16 KiB receipt or save another private file.

## Effects and limits

- The unchanged observation can create disposable private SQLite copies and perform read-only package queries; RPM may maintain its own bookkeeping. No production database, configuration, launcher, permission or service change is introduced by capture.
- If the unchanged preflight passes and the Owner explicitly invokes the diagnostic/probe flags, the existing finite six-service probe runs once and performs its existing bounded cleanup. There is no automatic retry or production resume.
- Capture timing can perturb the measured system. This invocation cannot attribute a previous failed invocation.
- Observed comm labels are names, not executable identity, daemon authority or proof that a change is benign.
- Private capture bounds: 4 MiB per writer sample, 2 MiB census, 32 MiB process details. Public supplemental output is at most 64 KiB, with at most 64 changed PID rows and explicit truncation.
- Capture has a cooperative 600-second ceiling, not a new probe watchdog. Separate stages bound prior authentication (60 seconds), outer download/compile (30 seconds), and final projection/output (10 seconds). The existing outer/probe deadlines remain in force. Uninterruptible kernel calls are not a hard real-time guarantee.
- Missing samples, ambiguous attribution, interrupted cleanup and missing durable hashes remain explicit UNKNOWN/HOLD. A supplemental report does not grant installation admission.

## Local validation

The frozen source and test hashes are recorded in RESULTS.json. All 56 local tests passed on Python 3.6.8 and 3.12.14 under -I -B -S with no skips. Independent read-only review reran the same 56 cases on both versions and passed.

Tests exercise the actual authenticated r6 CachedSources loader and original outer/observe_host/collect functions with synthetic lower-level IO, persistence and probe fixtures. They verify both full success and same-attempt writer mismatch, profiling absent at the mocked finite probe, partial persistence, wrong loader/cache/backend identities, interruption/disarm/deadline handling, bounded projection and secret-safe output. No actual host or finite probe was executed locally.

The test harness uses retained local r5 diagnostic fixture helpers and the strict locally verified r6 archive cache. These are local integration tests, not a newly registered Hosted gate. Existing immutable r6 Hosted evidence remains separate. Intermediate failed logs are retained locally; only the final two terminals support this freeze. No private raw reports, bytecode cache, credentials, configuration bodies or logs belong in the four-file publication allowlist.

Delivery remains pending an actual immutable publication commit and exact bootstrap pin verification. Owner invocation supplies action-time consent for one finite diagnostic/probe attempt; no older resume or installation approval is reused.
