# Epoch7 kit, protected loader and approval-gated composition

This is local kit tooling using the epoch5 explicit-source manifest and deterministic TarInfo/Gzip packaging pattern. The protected entry now wires the concrete factory and existing single-attempt coordinator. Final helper source provenance and the complete source-backed host inputs remain pending; no installation-ready artifact or production execution is claimed. Old `REFUSED_UNCOMPOSED` manifests still refuse resume. A separately reviewed `AUTHENTICATED_APPROVAL_GATED_SINGLE_ATTEMPT` manifest enables only the existing full approval-gated chain, never admission by itself.

## Files and trust boundary

- `build_epoch7_kit.py`: consumes an explicit input file map. Every target names one relative source and one exact SHA256. No source-directory globbing, private plan, host evidence, private fixtures, token, log, or upload capture is performed. Public fixture inputs have five exact source/target pairs: current runtime-derived service units, the 31-file official OpenClaw source profile, its one-file direct-entry extension, the MIT license and third-party notices. The extension is restricted to the exact1461-byte dist/is-main-DYSvvM1W.mjs official source and fixed SHA, with no additional host evidence. Unit bytes match the current manifest and15 public templates/renderings. The OpenClaw fixture is decoded and hash-checked against the recipe’s literal source map and fixed official version/commit/tar pins without importing or executing that source; the exact license/notice hashes are required. Inputs are read before output is created. The output directory must not exist.
- `epoch7_recovery_entry.py`: standalone stdlib bootstrap. The entry's own SHA256 must be independently verified before execution. Invoke with `-I -B -S`; the interpreter and its stdlib are trusted bootstrap dependencies. The independently supplied kit-manifest digest binds the exact runtime SHA, `runtime_source_commit/tree`, separate `kit_source_commit/tree`, sources, test sets and exact resume capability mode. Helper source pins must come from the later actual frozen-source commit/tree; a runtime-only commit is never presented as containing those helpers. Commit the source bytes first, then generate the map/manifest outside that source commit to avoid a self-reference. There is no hardcoded claim that an old checkpoint is the final runtime.
- `extract_epoch7_kit.py`: standalone stdlib bootstrap, never imports kit code. Requires archive, entry and kit-manifest digests before extracting. Rejects archive aliases, traversal, duplicate members, links, devices, unexpected permissions/owners/timestamps, extra files/directories and changed member hashes. Decompression/member/file bounds and exclusive no-follow writes prevent unsafe extraction or overwrite. Its output argument is the new exact `epoch7-recovery-candidate-r2` directory under the existing protected candidate parent, not an additional wrapper directory. Independently check this bootstrap script before using it.
- `run_epoch7_offline.py`: standalone unprivileged Linux/hosted-CI runner. It authenticates the entry before execution, verifies all kit bytes under root/current-UID ownership, requires the exact helper-source commit/tree and the full explicit portable-suite set, and imports the fixed pure helper closure to reject missing transitive imports. It has no observation/probe/resume option. Evidence explicitly labels Python version/UID and does not claim UK or production validation.
- `audit_epoch7_imports.py`: scans the exact SHA-bound map with AST traversal, including function-local and literal dynamic imports in production modules, test bodies and every shared test-fixture alias within its consuming suite. Missing required imports fail. Disabled-suite missing imports and nonliteral/direct-loader sites are explicitly reported for review; this does not execute candidates or prove dynamic execution safety.
- `portable-tests/ADAPTERS.json`: exact original/adapted SHA values and narrow location/import changes for reused runtime identity, integration and help tests. Process and inode assertions are retained. Fixture-bearing FD/resource tests use only the verified disposable copy’s confined helper fixture roots. One historical unit assertion is explicitly updated from zero supplementary groups to exactly the reviewed dispatcher group, rejecting extra grants. Temporary SQLite/socket/process fixtures are outside the kit.
- `staged-runtime-test-harness.py`: temporary local evidence harness for the already frozen runtime while helper-source freeze is pending. Its exact runtime/test input map authenticates cached imports and rechecks runtime inventory afterward; it never fabricates a full-kit source commit or a kit admission result.
- `test_epoch7_kit.py`: confined synthetic local fixtures and mocked observation/probe/resume boundaries. No production host, network, real systemd or recovery action.
- `input-map.template.json`: explicitly enumerated public inputs. Mutable helper/test/entry SHA fields and actual helper-source commit/tree are deliberately null, so the builder refuses this template until actual frozen Git bytes/pins are supplied. Runtime rows now bind the real rebuilt 101b465c/26ae package; helper/test pins remain null until their separate source freeze. Add any final factory/test filenames explicitly before freezing. `superseded-input-map-v1.json` and checkpoint-a/b are historical development artifacts only.

Before publishing or importing, package provenance is cross-checked against the explicit runtime source commit/tree, manifest path/hash/files and frozen verifier path/hash. This is a pure internal consistency check, not a network provenance claim. Every kit file is authenticated before a candidate module is imported. Descriptor-relative no-follow traversal checks all ancestry, owners, permissions, access/default ACL absence, single-link regular files, and before/after descriptor/path metadata. Exact directory inventory rejects extra empty directories, bytecode, and unlisted content. Reads are bounded and directory bindings are rechecked after verification. Candidate Python modules execute from cached authenticated bytes, rather than reopening sources through normal Python import machinery. A candidate preloaded in `sys.modules` is rejected. Imports outside the declared map are limited to the isolated interpreter's initial stdlib path.

The normal CLI requires root and root-owned protected ancestry. Offline test APIs explicitly supply fixture UID/GID; there is no CLI switch to weaken production authority.

## Operations

- `verify-only`: authenticates the entire kit and reports only hashes/counts. No candidate import or host collection.
- `test-only --suite NAME`: runs exactly the named enabled suites from cached bytes, then verifies the full kit again. Cross-suite fixture imports are explicitly enumerated. Filesystem suites run in a byte-identical authenticated disposable copy outside the protected kit; only that copy receives the fixed helper fixture directory. The copy is verified before tests and after empty-only fixture cleanup, then removed. The protected original is reverified even if a test/import/cleanup raises. Each logical test suite has its own directory and fresh module namespace, so the same test basename in different suites does not collide.
- `observe-only --output PATH`: imports the verified observation collector, validates the exact staged root and an absent fixed-scope private output, and calls `observe_host(candidate_root=...)`. The collector takes the existing host locks and retains HOLD metadata. `persist_private` performs a new O_EXCL0600/fsynced/readback-verified private write. Standard output includes only fixed status and digests.
- `observe-and-probe --output PATH --nonce 32_HEX --execute-reviewed-probe`: the same observation followed by at most one finite diagnostic, and only after complete unreviewed ingredients, exact staged-source evidence, source revalidation and a non-HOLD snapshot. The schema2 compiler receives cached driver/helper/runtime hashes and the original completed observation. The reviewed scope also includes the pinned unprivileged Node builtin in-memory SQLite TEXT/BLOB/JSON capability diagnostic; it does not import OpenClaw or open a disk database. The separately authenticated node_sqlite_probe helper validates the exact measured Node binding and proof before whole-probe success can be reported. Old schema1 policies cannot authorize this added effect. The probe's callable preserves its real signal watchdog and cleanup. Results are retained privately, including uncertainty. A snapshot HOLD never automatically gains an exception.
- `resume`: allowed only for the explicit composed-candidate manifest mode, fixed UK host/root/staged path, complete hash-bound private inputs and a real fresh PR58 review ID/body hash. The entry calls `prepare_host_inputs`, compares `compile_host_contract` against the exact approved plan, constructs `assemble_host_driver`, and invokes `resume_once` exactly once in the same authenticated import scope. Any compiler HOLD or component mismatch stops before assembly. There is no compatibility fallback, approval-fetcher override, retry loop or loader-owned cleanup.

The probe flag is only an acknowledgement. It is not cryptographic proof, independent acceptance, or a substitute for prior explicit Owner action-time approval of the exact nonce, permissions, finite actions and cleanup scope. This source kit does not obtain that consent. The caller must use the independently hash-pinned manual command after consent. No production resume authority results from the probe. A complete observation does not approve a recovery plan.

The observation root is fixed to the existing candidate directory plus `/epoch7-recovery-candidate-r2`. Its output must be a new `epoch7-observation-<16 lowercase hex>.private.json` directly under that existing candidate directory. No preparation directory or host lock is created by this loader.

## Private recovery input wire contract

The approved plan and seed are separate root:root0600 single-link regular files under the existing protected candidate parent, outside the public kit. The exact names are `epoch7-approved-plan-<16 lowercase hex>.private.json` and `epoch7-resume-inputs-<16 lowercase hex>.private.json`. Both exact SHA256 values are explicit command inputs. Plan bytes are bounded to2MiB; the seed is separately bounded to64MiB (including the collector’s bounded private source-review inputs). No-follow ancestry, ACL, owner/mode, size, descriptor/path race and digest checks apply before and after pure composition. No private bytes, exception text or command output is printed.

The seed envelope is exactly `{schema: 1, seed: {...}}`. Its11 fields are observation, compiled, additive_deltas, identity_payloads, activate_retained_renewal_timer, native_before, tls_journal_before, prior_provision_bytes, legacy_units_raw, publisher_journal_raw and sandbox_candidate_raw. The six raw fields and two fixed identity-policy values are UTF-8 strings converted byte-for-byte, preserving whitespace/newlines. `compiled_bytes()` converts only its existing three known compiled byte fields. Generic byte sentinels, arbitrary path references, pickle and callable/provider overrides are unsupported. The factory independently verifies retained raw-buffer hashes and all semantic binding.

Five fields can only come from authenticated cache: installer_source, exact source_manifest_raw, all107 source_payloads, artifact and kit_manifest_sha256. Seed attempts to substitute them are rejected. Candidate24, boot state, service facts and all remaining measured policy/checkpoint rows are derived by the factory from the same approved observation; the entry never replaces it with a newer snapshot or asks the Owner to author future process/checkpoint pins.

The existing observation keeps `finite_probe` as its original attempt, including the exact policy and result. Before preparation, the loader reads only `/run/xj-p2-proof-<32 lowercase hex nonce>/created-receipt.json`: existing root:root0600, single-link, no-follow, no ACL, bounded128KiB, stable metadata and exact reported SHA. The authenticated pure receipt validator derives the original policy digest from those protected bytes, checks the single exact Node SQLite event, diagnostic source, complete finite probe and cleanup, and binds the original observation with only `finite_probe` removed. Caller-supplied digest equality alone is insufficient. The identical receipt/proof binding is rechecked before assembly. No observation duplication, new seed field, caller trust flag, receipt creation or probe retry is introduced.

An eventual independently hash-pinned manual invocation uses `--operation resume --approved-plan PATH --approved-plan-sha256 SHA --private-seed PATH --private-seed-sha256 SHA --review-id ID --review-body-sha256 SHA`, together with the verified `--kit-manifest-sha256`. These arguments do not authorize execution: the existing authenticated PR58 verifier and coordinator enforce the complete approval and live preconditions. No probe acknowledgement grants recovery authority. The loader reports only bounded fixed statuses and digests. Tested KeyboardInterrupt/SystemExit outcomes remain nonzero and coordinator uncertainty never becomes success. ## Exact published-source CI generator

`run_published_kit_ci.py` accepts only the fixed published helper prefix and tracked runtime directory. `public-source-index.json` has exactly schema1, kind `EPOCH7_EXPLICIT_PUBLIC_SOURCE_INDEX`, files, tools, modules, test_suites, production_resume and the three fixed runtime source/manifest pins. Each files/tools row is exactly `{source: repository-relative-path, sha256: exact-bytes-sha256}`. File keys are logical non-runtime kit targets; tool keys are paths under the fixed prefix’s tools directory. The index excludes itself and has no helper commit/tree fields.

The generator gets actual HEAD/tree from bounded local Git reads and checks every indexed file plus all110 runtime package files against both current filesystem bytes and the exact HEAD blob. It authenticates the entry from its indexed Git blob before using its protected file reader. It generates the complete map with that actual helper-source provenance in RUNNER_TEMP, audits required imports, runs the separately reported full bootstrap/resume/CI-tool tests from exact cached tool bytes in disposable staging, builds twice, compares archive bytes, extracts through the hash-gated extractor and runs the real isolated offline runner on the extracted kit. No generated map or archive enters its own source commit.

Git captures and test logs use bounded regular files. The subprocess helper never calls communicate or uses pipe capture; it keeps the child leader unreaped, verifies group/session ownership, signals the owned group before reaping, and uses a two-second reap bound. Overall remaining-time budget is540 seconds, individual Git calls15 seconds, and the test child at most480 seconds. The workflow’s outer wrapper must enforce600 seconds. Unknown cleanup never becomes success. Default process death/SIGTERM has the same limits described above.

The output directory must be a new direct child of RUNNER_TEMP. `ci-summary.json` contains hashes and exact terminal test results; `mandatory-tests.log` and the separate `bootstrap-tests.log` contain only public synthetic test output. The summary’s bootstrap_tests object reports its own exact tests/failures/errors/skips, exit status, source hashes and log digest; candidate-suite success cannot substitute for it. Missing required files/imports, empty suites, skipped required cases, hash drift, a nonzero test command or unavailable terminal results fail CI. Fixed phase/error-class/internal-code fields preserve failure location without printing external exception text; the workflow may always print the last200 lines of the fixed test log. No upload action, secret, model download, package/network installation, self-hosted runner or production host operation is used.
