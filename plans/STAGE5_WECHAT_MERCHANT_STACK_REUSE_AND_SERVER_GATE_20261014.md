# 社区分账系统：微信渠道、开源复用与服务器落地前置

日期：2026-10-14。来源：Owner补充及 Stage5 原需求。状态：DOCUMENTED_ONLY / HOST_VERIFICATION_NOT_RUN / PRODUCTION_DEPLOYMENT_NO。

## 必须交付的五个界面与后端
1. 商家展示前端（商家主页、门店、商品/服务、活动、地址、客服、支付入口）。
2. 微信小程序消费者端（商家展示、扫码/场景关联、金额输入、支付中与服务端已核验的收据页）。
3. 公众号H5消费者端（对应的微信内网页，按公众号OAuth/JSAPI实际权限接入）。
4. 商家管理后台（自有门店、员工、订单、退款、结算/分账查询、广告与展示素材）。
5. 平台管理员后台（入驻审批、跨商家运营但受限授权、支付通道与分账规则、审核、风控、财务对账、系统审计）。

**共同后端**：租户RBAC、店铺、支付订单、支付服务商适配、回调/查询对账、退款、分账指令/结算、广告引擎、操作审计。广告独立失败降级不影响支付。

## GitHub与落地约束
- 当前可访问仓库是否有独立Stage5业务仓库：NOT_FOUND_IN_CONNECTED_ACCOUNT（不等于其他不可见仓库不存在）。
- Control repo 仅留需求、脱敏合同、离线测试与审批索引；业务实现先取得正式业务仓库及受保护CI权限，不默认往控制仓库开发生产后端。
- 初始化目标仓库前需明确：owner/repo、微信小程序和公众号各AppID引用、支付商户号/服务商与分账产品能力、租户身份授权、运维维护者。Secret只保存SecretRef；不要上传实际值。
- 发布门禁：审源码/开源许可/SBOM、软件供应链扫描、测试环境含虚拟支付数据的E2E、真实微信支付API沙箱或官方测试能力、签名回调/查单/退款/分账对账、数据加密和权限、部署回滚/Canary、独立审计。
- 小程序发布审核、公众号主体认证、支付商户号与分账开通状态、广告合法性与分账资金流法律约束均为UNKNOWN，不能以本设计充当已获权限证据。
