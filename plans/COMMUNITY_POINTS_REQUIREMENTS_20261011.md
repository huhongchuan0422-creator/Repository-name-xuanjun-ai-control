# 社区分账小程序与商家积分需求 — 2026-10-11

## Owner本次确定的规则

前端以小程序展示。积分领取主体是实际完成社区分账的商家；不得将规则自动
改成消费者返积分，也不得与云汇CP或推荐奖励合并。保留既有社区支付/分账
及两个广告位需求，优先复用其账务、订单、商品、商户和权限资产。

| 项目 | 确定规则 |
| --- | --- |
| 获取 | 每实际分账给社区0.1元得1积分；1元得10积分 |
| 用途一 | 平台爱心/义卖商城兑换爱心物资 |
| 用途二 | 平台合作联盟商家消费抵扣现金 |
| 兑换面值 | 10积分=1元 |
| 商户比例 | 受理商家在后台自行配置10%–30%的单笔抵扣上限 |
| 单笔约束 | 实际抵扣不得超过消费金额乘该商户设定比例，且不得超过可用积分 |
| 有效期 | 从获得之日起一年 |

例：商家实际给社区分账1元，获得10积分，可抵1元。联盟消费100元，受理
商家设置20%，该订单最多抵20元/200积分；只有50积分时最多抵5元。
设置10%或30%时分别最多抵10元/100积分。商城兑换以商品公布所需积分和
真实库存为准；消费抵扣比例不自动套用到物资兑换。

## 本次落实的工程验收要求

- 金额使用整数分，积分使用整数；不使用浮点进行资金或抵扣计算。
  每笔订单抵扣积分上限=floor(floor(可抵扣消费金额分×比例)/10)。
  商家实际分账金额及其可归属凭证必须先确认，不能以待支付、分账意图或
  失败回执发积分。金额不够10分的余数如何累计及支付/运费抵扣基数属于
  业务边界，实施前在同一需求版本记录，不静默截断、不擅自扩大返奖。
- 以已完成分账凭证和商家身份作幂等来源；重复回执、重复请求、重启不会
  重复发积分。分账冲正/退款按原来源记反向流水；已消费的积分需记录待
  清算责任，禁止覆盖历史余额或为了等待积分清算阻塞依法/依约应有的退款。
- 积分按发放批次存期限。抵扣/兑换优先使用最早到期有效批次；预占、确认、
  取消与到期原子处理，防并发超扣。取消返还沿用原批次到期时间，不重新
  延长一年。有效期日历定义和闰日边界在实施版本列明并测试。
- 商家后台只能设置自己商店的10%–30%，后端也校验边界。订单冻结当时
  比例、金额基数、积分面值和规则版本；后续改配置不追溯改变已确认订单。
- 分账资金、积分发行/消费/失效和联盟/商城结算分别有可对账流水；积分
  抵扣后的商家补偿及物资成本承担方需落实账务规则，不能假定“无成本”。
  未知成本、结算责任保留UNKNOWN，不以积分数代替真实现金收入。
- 权限按商家、联盟商户、订单和租户限制；不可查看别店积分或跨店修改
  比例。小程序登录态只作身份入口，服务端验证每次交易与幂等键。
- 验收至少覆盖1元→10积分、10积分→1元、10%/30%边界、越界配置拒绝、
  积分不足、到期/批次顺序、重复发放/消费、并发预占、取消/退款、库存不足、
  分账失败、重启及流水对账。不以静态前端预览代替真实支付/分账验收。
