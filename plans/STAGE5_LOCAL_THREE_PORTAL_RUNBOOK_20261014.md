# Stage5 本地模拟三端统一运行与整体验收门禁

**适用范围**：本仓库Stage5本地开发模拟，不是微信收款、服务商结算或生产业务系统。以 Issue #76 为统一任务入口。PR94→PR101→PR103→PR104→PR105 源码依赖未按顺序审验合并前，不得把本文件当作已交付生产声明。

## 一套服务、三个入口

在可信开发机器、已安装Python 3.12、从带有所有模拟服务提交的工作区根目录执行：

```bash
python -m scripts.community_demo_api
```

默认HTTP绑定 **127.0.0.1:18791**，不允许对外网卡暴露；前端、服务端共用进程内单个SQLite模拟订单数据库。仅可从运行机本地访问：

- 消费者模拟：`http://127.0.0.1:18791/demo/`
- 商家只读模拟：`http://127.0.0.1:18791/demo/merchant/`
- 平台只读模拟：`http://127.0.0.1:18791/demo/platform/`

消费者在金额输入后创建模拟订单，商家和平台使用相同租户/商家/门店/订单编号查询状态。消费者再提交模拟事件后，其他两页再次查询以验证终态。**模拟 SUCCESS 不构成支付渠道确认**；两后台显示验证“否”。重启 `:memory:` 服务会清空模拟订单。

## 统一精确代码门禁

`.github/workflows/stage5-full-local-gate.yml` 使用PR的 `head.sha` 而不是旧的合并预览；集中执行Stage5的Python合同/SQLite/HTTP测试、消费者及两后台JavaScript交互、真实Chromium浏览器三页共库E2E，且仅使用GitHub Hosted Runner，不调用东京/韩国/英国自建Runner。

该门禁覆盖源码回归与已存在的浏览器演示范围；**不代表P1-01至P1-15全部验收**。特别是：

- 当前页面中的租户/商家/门店字段属于自报模拟输入；不存在可信登录会话或平台/商家RBAC后端。
- 商家资料/商品/广告虽有独立可信SQLite聚合源，尚未实际接入本演示HTTP同源链路。
- 两广告位在演示页面仍为静态占位；真正付款成功广告只能在服务商可信回执核对后显示，不能依据模拟SUCCESS释放。
- 目前没有真实微信小程序构建/公众号H5发布、真实付款/退款/分账/调账/结算、受保护恢复及备份、正式生产域名与英国部署验收。
- 任何CI绿灯都不得改变 `PHASE1_ACCEPTANCE=NO` 或生产写入权限。

## 故障停止

一旦发现租户/门店隔离失效、模拟付款显示真实已结算、旧请求覆盖新订单、UUID冲突、非本地Host/Origin可读写、异常广告阻断正常商品、或支付成功广告未经真实回执放行，应保持Draft/HOLD，写入GitHub原任务并回归测试。生产凭据与敏感客户信息不得进入公开Actions日志。
