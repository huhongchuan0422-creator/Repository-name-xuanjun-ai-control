## 平台自动化目标澄清

本方案面向建成后的玄钧云汇平台后端：AI接待 → 客户预充值 → 定制开发或功能选购 → 客户确认平台订单 → 后端自动付款采购服务器 → 部署 → 验收上线。它不是要求聊天助手代付未来每一笔订单。客户订单、资金与商户/API授权有效且满足下述策略时，普通平台订单可自动推进，Owner无需逐单再确认，也不要求平台接入聊天支付工具。客户预充值本身不是具体订单确认；报价与条款应在订单或明确的有界持续委托中接受。供应商、支付机构或适用规则确实要求额外认证/确认时进入异常处理，不绕过。

## 3. 自动付款的完整预授权合同

配套 `server-order-preapproval.schema.json` 记录已明确的政策及尚待绑定的字段，不是已激活执行配置。已明确的供应商、金额和客户资金规则不再重复索取。下列字段在真实订单或已批准的有界采购政策中绑定：

1. 授权主体：authenticated actor、tenant/project、是否有billing权限、资源所有者、采购人/合同主体、付款账户所有者、可信来源、授权时间/有效期、撤销版本、一次或持续授权范围。
2. 供应商与商品：供应商固定为阿里云，其他云商拒绝；订单绑定允许的服务/SKU/配置、地域、数量、计费周期、币种和可接受替代规则。不能自动换服务商或换付款主体。
3. 金额：含税、必选费用、部署/设置费、必要存储/带宽、标准交付和其他强制费用的单次完整采购订单总额≤CNY 10,000；禁止拆分同一采购需求、分期扣款或重建订单绕限。每笔同时受对应客户可用预存资金约束，并原子预留，不能占其他客户资金或由Owner账户余额补贴。押金、预授权、待结算付款和已接受但尚未开票的承诺纳入占用；退款确认前不释放。月度累计上限目前NOT_SPECIFIED，保留累计观测，不能假称获批无限预算；它不抹去已经明确的单笔授权，也不凭空增设用户未要求的月度金额。当前仅CNY金额界限已明确；其他币种/FX报价先HOLD并取得可核CNY总价或明确汇率上限，不自动换算扩大授权。
4. 支付：使用现有英国服务器所属阿里云账户；真实账号UID/account ID及现有支付方式的非秘密引用必须受控验证并固定，不能凭名称猜测。该账户承担云商付款，但平台必须先证明对应客户订单资金充足且已独占预留。一次/订阅/按量类型、付款资格与资金来源逐订单绑定，不保存/展示卡号、Token或密钥。
5. 交付：批准的云账号/组织/订阅、tenant/project、地域、域名或目的地、资源标签、管理人、已有密钥引用或安全交接方法；必须读回归属后再部署，不能交付到执行者默认账户。
6. 期限与续费：是否自动续费取客户该订单经认证的明确true/false，未填写不等于同意。每次续费同样总额≤CNY 10,000并有足额对应客户资金；还要符合客户批准的续费价格/允许涨幅、配置、频率、期限/次数、提示和取消截止。不能因为首单付款成功自动开启续费；未提供的月度附加上限保持NOT_SPECIFIED。
7. 商业条款：准确条款URL/版本或hash、价格有效期、履约/交付方式、可见取消收费、退款/退货限制、承诺期、SLA及相关附加服务。新增条款需要披露并按相应规则接受；不能把报价确认换成长期新条款接受。
8. 行为许可：明确允许自动下单与付款、是否允许在客户未逐字复审内容时发送指定供应商订单/指定客户通知、允许的数据/接收方/目的、允许的部署release范围；如果需要CAPTCHA，可在本次清楚说明的订单确认中一并取得许可，不能自行假定。

付款准入为：平台授权有效 ∧ 英国服务器所属阿里云付款账号已核实且商户/API扣款授权有效 ∧ 租户订单授权有效 ∧ 商品/交付匹配 ∧ 当前条款及供应商实际认证要求满足 ∧ 全价CNY金额≤10,000且无拆单 ∧ 同租户可用预存资金原子预留成功 ∧ 云商账户实际可支付 ∧ 未撤销/过期 ∧ 无同订单未知付款。Owner自己付款且拥有资源的自营订单可由同一主体满足多个角色；客户自己付款或使用其账户时不能由Owner替代客户确认。

平台后端可依据有效客户订单确认、足额同租户预存资金及合法商户/API扣款授权，在固定供应商/账户和全价上限内自动采购付款、接续部署。无需Owner为每个正常平台订单再次确认，也不把聊天助手工具的交互式审批方式作为后端必要架构。供应商或支付机构要求的SCA/3DS、额外付款确认、条款接受及其他适用要求仍必须满足；仅这些例外或越界/未知结果进入人工处理。首次安全凭据交接、持久OAuth/API授权创建或扩大、相关安全配置及正式自动付款通道激活，仍需精确审核和对应动作时确认。当前付款自动化未实施或激活。

按量云账单不一定有供应商硬费用上限。只有风险可界定且用户接受的费用模型才可自动购买；不能用“预算告警”冒充硬限额。上限无法保证、价格/汇率/币种/商户/条款/交付/订阅实质变化、无匹配额度或授权缺失时，生成一个汇总订单决策请求并HOLD，不擅自选默认值。

## 4. 自动订单到部署状态机与确认边界

[阿里云ECS RunInstances官方接口](https://www.alibabacloud.com/help/en/ecs/developer-reference/api-ecs-2014-05-26-runinstances)提供AutoPay参数：true可自动完成付款，false生成未付款订单；PrePaid订单返回订单ID。创建是异步过程，必须查询资源状态；云商账户余额不足可能产生异常订单，不能盲重买。该接口证明平台自动采购具备产品能力，不证明本项目账号、API权限、付款资格或生产接线已验收。

复用现有订单/支付记录和canonical执行标识：REQUESTED → QUOTED → AUTHORIZED → BUDGET_RESERVED → SUBMITTED → PROVIDER_CONFIRMED → RESOURCE_DELIVERED → DEPLOYMENT_ADMITTED → VERIFIED → OPERATING。每次副作用前先durable intent，结果持久化；超时、重复回调、响应丢失进入UNKNOWN_RECONCILIATION，查询同一provider order/payment ID而非再次购买。

- 报价边界：把供应商、规格、全价、币种、单次/续费、所有者、交付账户、条款/退款、部署范围和必要安全交接集中呈现。客户已确认当前订单，或其明确有界持续委托完全覆盖当前报价时，平台机器完成范围、资金与额度核准并自动提交；Owner无需重复确认。未覆盖时由实际有权的客户/付款主体一次确认订单与付款，供应商确需的额外认证再转例外流程，不逐步询问。
- 预算边界：所有并行订单对同租户预存余额原子预留，余额扣除已付款、退款争议、预授权及其他未结承诺后才可用；同订单重试不重开额度，取消/失败只有供应商确认无费用/预授权解除后才释放。按完整客户采购意图关联订单防拆单，每日/月度换窗不得抹去长期承诺；自动续费、扩容与按量费用计入同一适用资金约束。月度金额上限未配置，但累计支出持续可见。
- 客户收款与供应商付款是两笔不同交易：客户已付款不证明云商已收款，云商扣款也不证明客户应付已结清。需要按订单、主体、币种与实际确认状态分别对账，不混用账户或跨租户补款。
- 资金事实来源：预存余额只由既有付款系统验证过的已结算收款和可信调整记录产生；前端金额、客服备注、付款截图或客户声称已支付不能入账。支付Webhook必须核可信来源/签名、商户账号、tenant/order、金额/币种、事件ID和重放窗口，并与供应方查询结果对账；重复/乱序回调不重复记余额或放行。退款、撤销、争议/拒付与未决收款立即影响可用余额，不能把总余额当可支出余额；不把平台预存服务余额改造为跨客户转账或金融产品。
- 资源边界：付款成功仍需核资源真正建立、指定账号/地域/配置归属、费用和访问状态。没有资源不宣称部署完成；安装/接入失败不自动重买。
- 发布边界：将已审制品、客户验收/发布范围、目标资源、备份、回滚、维护影响集中准入；已明确授权的同一release内机械步骤自动进行，代码或风险实质变化才重新确认。采购许可不替代生产发布和持久接入确认。
- 续费边界：按客户订单选择复核当前服务、未撤销、价格/条款/≤CNY10,000、对应客户资金、剩余次数和期限。客户未同意自动续费时不付款；客户余额不足时按既有明确政策关闭该精确服务器自动续费并读回状态、通过订单已授权的客户账单通知渠道告知原因/到期日/补足办法，同时记录Owner可见异常。不得提前关机或删除，不跨客户调款或以Owner资金补贴。关闭接口失败/到期扣款已在途时记录UNKNOWN/HOLD并对账，不宣称已关闭；补足余额也不擅自重开自动续费，须有客户有效订单选择且同版本条件仍成立。
- 云商扣款窗口：供应商自动续费会直接扣付款账户，不能仅在到期时看一次客户余额。须核阿里云实际续费扣款/重试/关闭截止规则，在每次可能扣款窗口之前锁定足额对应客户资金，核客户续费委托及商户/API扣款授权，并满足供应商实际要求的附加认证；资金预留不能被并发订单/退款重复使用。无法证明扣款窗口、取消已在途效果或持续足额锁定时，不启用不受控的供应商自动扣费，使用客户已经同意、资金与商户/API授权齐备的受控后端续费订单；只有供应商确需额外认证或超出委托范围时才需人工。余额不足的关闭操作不等于尚在途扣款必然取消。
- 失败边界：优先保留用户数据、审计与恢复能力。无授权不因超预算自动永久删资源；停机、退订、退款和数据删除分别按既定动作/可逆性/合同门禁处理。供应商侧无法撤销的付款、税费或外部效果如实保留。

## 6. 最终业务目标：从推广到持续运营的全流程自动化

本节记录长期目标和最终验收方向；当前优先完成既有P2及本次送审批次，不因此新启动架构改造、采购、生产部署或新任务队列。

Owner的最终目标是玄钧云汇全部业务自动运行：推广获客 → AI咨询 → 统一客户身份/CRM → 需求与报价 → 客户确认订单/付款 → 选购现有模块或定制开发 → 测试与独立审核 → 必要的服务器采购、部署上线 → 客户验收 → 持续运维、续费、售后退款与客户留存。正常、已授权且门禁满足的业务，Owner操作步骤目标为零；客户真实下单、必要授权和验收仍是客户自身业务流程，不能由平台伪造。只有法律/供应商强制核验、争议、越界、风险或无法核清的外部效果进入有界异常处理，不把日常交付变成人工转交。

实现沿用既有业务文档8.2.3–8.2.8、XuanJunAI_ServiceBot、现有模型路由、CRM/租户RBAC，以及本包[18类权限矩阵](README.md)和[基础验收](acceptance-tests.md)。以原任务、订单与canonical执行标识关联现有系统；不建立第二权威账本、第二队列或替代架构。P2/P3是执行与接续基础，P2/P3完成不能表述为全部业务已自动化。上述既有组件的实际接口/当前部署及以下端到端接线，本补充均未重新实测，保持UNKNOWN/NOT_VERIFIED。
