## 2. Three connected stages

No request can choose a verification mode. No extraction. Selected link/hardlink and all sparse entries are rejected; unselected link headers are never followed. It never creates jobs, fabricates metadata SUCCESS, creates a queue DB or runs material. Metadata collector UID and local root custodian are distinct, explicitly configured responsibilities. Existing completed deliveries may be reconciled/verified without source reread; partial/unknown state is retained and requires review, not blind replay.
3. `OAuthProjectResource` optionally uses explicitly enrolled `custodies` rather than source roots. Its received-file path performs SELECT-only original job, delivery SUCCESS/full offset and final offset=-1 SHA proof checks, then verifies the exact binding-derived .bin through NOFOLLOW, owner, 0600, nlink=1, length and full SHA. It does not instantiate Receiver, reconcile, read source/tar, or fall back to source on missing custody.
