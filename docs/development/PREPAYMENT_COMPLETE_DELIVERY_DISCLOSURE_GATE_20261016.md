# 定制开发付款前完整交付条件披露门禁 V1

Owner规则：每个定制项目在报价、签约和付款前一次性告知所有可预见的上线前置条件与总拥有成本，不得收取开发定金后才陆续发现客户缺少域名、ICP备案、证书、服务器或第三方资质。状态 OWNER_RULE_REGISTERED / INTEGRATION_PENDING；沿用现有CRM、Commercial/Price Book、Finance、Project、SecretRef及PR122客户资料清单，不建重复系统。

## 强制售前核验矩阵
需求范围/交付物/客观验收；客户主体及原签约资格；客户自有或代购域名、域名持有权和实名认证；网站/APP/小程序及业务所在地的ICP备案/APP备案、是否需要软著与第三方平台资质；TLS证书（默认先评估免费可自动续期证书）；ECS/SWAS、带宽、RDS/OSS、备份、日志、监控、灾备；支付商户资格/分账、地图、短信、AI模型等第三方能力、接口权限和实付费用；客户应提供的文件、OAuth/SecretRef密钥及其获取教程；开发排期、审批等待与上线时间区别；保修维护、续费、退出/迁移/数据交付及退款责任。

每个条目必须有 required=YES/NO/PENDING、applicability_reason、owner、supplier、official_price_cost_status、customer_action、deadline_or_unknown、dependency_gate、instructions_url、evidence、contract_version。PENDING/UNKNOWN不得作为已完成通过，不得编造备案期限、实时云价格及支付牌照。

## 一次性商业报价
对客户输出「项目完整方案与准备清单」及同版本Price Book：一次性开发/部署/域名首购等、持续域名/服务器/API/维护费、可选模块分别列项；第三方本金与玄钧服务费分列、CNY/USD双币展示，实际支付币种单独标注。预计费用、价格波动项及锁价/有效期逐项说明。未确定的重要费用不能写0或隐藏在合同脚注。

PAYMENT_ORDER_GATE：不得在尚未形成完整披露方案、范围和总拥有成本说明以及客户明示确认前创建正式开发付款订单；可以允许客户在知悉尚未办好的备案/资质情况下签署分阶段开发合同并支付定金，但合同必须列明上线HOLD条件、责任人、周期不确定性、取消与退款/变更规则。不得因客户付款后发现既有可预见必备条件而无依据额外收费。

## AI自动化交付与验收
售前AI按项目类型自动生成上述矩阵和申请教程，必要条件随客户材料提交逐项满足；客户可分批交资料，但平台首次报价必须一次列明已知全部要求。正式价格/订单由既有Commercial与Finance审批签发，AI不自动批准未知成本；后续自动采购域名/服务器、部署TLS/DNS、等待法定备案核验、测试/交付和续费核销均沿用受控任务事件链。

反例测试：已收定金后才披露域名/备案/支付商户资质为BLOCK；免费证书不可自动续期却宣传零维护为BLOCK；UNKNOWN第三方费用写0为BLOCK；客户拒绝资质时错误宣称可在国内正式上线为BLOCK；项目无需独立域名却强制收费为BLOCK；合法的客户知情分阶段付款需允许，前提合同已完整披露。
