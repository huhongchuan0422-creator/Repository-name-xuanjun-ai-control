# 玄钧云汇全项目开发、审核与交付规则 V2026-10-19

Owner于2026-10-19（Asia/Shanghai）确定。本文件适用于全部现有及未来项目，作为开发架构文档的执行补充；与旧文档中角色、逐次安装许可、5次上限和大型批量交付方式冲突时，以本文件为准。业务需求、资金权限、凭据保密及平台安全限制继续适用。规则登记不等于调度器、执行通道和生产代码已经适配。

## 1. 职责与完整流程

- Owner：提出目标、范围与验收要求，处理真正需要人工决定的升级事项。
- Dots：任务分派、动态调度、监督、集中独立审核、失败方法裁定及最终证据核对；不得自审参与编写的代码，参与开发时交另一独立审核者。
- ChatGPT执行实例：开发、测试、自检、集成、部署安装、故障诊断、安全恢复、实机功能验收。每个项目指定一个交付/集成负责人，每个生产目标保持唯一执行Writer。
- Work：与Owner对接、架构设计、需求澄清和文档补充；不进入开发自动化执行闭环，不接管产品Writer或增加审批节点。

流程：Owner → Dots分派 → ChatGPT开发/测试/自检 → Dots集中审核 → ChatGPT直接部署安装及实机验收 → Dots核对证据后关闭节点。
Dots通过的准确版本和范围即可进入既有授权内的部署，不再另设安装许可、逐次Attempt审批或人工搬运现场材料。必要现场检查由执行流程内完成并留证；不能省略真实状态判断。版本变化需增量审核，不能借旧通过记录部署未经审核代码。

## 2. 最小独立功能节点

必须尽可能拆成能够独立使用、测试、部署、验收并关闭的小功能节点；禁止将几十个独立功能捆成一个大型任务、等全部代码写完才测试、等全部功能完成才安装。
每个节点记录：原任务引用、节点ID、功能目标、边界、依赖、负责人、允许修改路径/接口、测试、部署范围、验收标准、恢复方式。
一个节点完成开发 → 测试 → 必要独审 → 安装 → 实机验收 → 冻结关闭，再推进其后继；依赖独立的节点可以并行。不能把安装步骤拆成几段冒充独立功能。已关闭节点只复核后续实际影响的接口与依赖，不重复安装。
当前P2例外：保留已接近安装的完整既有方案，不为本规则重新拆F1–F8；只有实际失败证据支持结构调整时再裁定。以后新增功能遵循小节点原则，禁止扩大本例外。

## 3. 多ChatGPT动态并行

Dots根据项目数、可并行节点、依赖、执行资源及既定额度动态决定实例数；串行依赖不因增加实例而变快，不为凑人数重复工作。
每个实例使用独立分支/工作区、明确路径和接口；共享核心文件、数据库迁移及集成分支由指定单Writer负责。
交付负责人收齐子节点、解决冲突并运行集成测试后交Dots；生产同一目标部署保持单执行者和真实锁/Fence保护。
调度器必须提供实际运行ID、心跳、检查点、提交/测试结果和退出状态；“已分派”不等于“已启动”。接管前确认旧实例停止或被有效隔离，不制造第二Writer。
自动启动、唤醒和接续须使用实际接通且获准的执行接口；不得把聊天窗口指令或计划冒充后台任务。

## 4. 集中审核，禁止发现一项就退回

审核前读取本规则、原任务最新检查点及唯一审核清单；记录规则版本与准确源码/Tree/比较基线。
先完成全部可独立审核范围，再集中输出。一个缺陷只阻塞对应判断，不停止其他合法源码、测试、制品核验。
唯一清单每项必须记录：已审通过、确认缺陷、缺证据、受阻未审之一，以及证据、影响、责任方、最小修复和验收标准；无证据不得填PASS。
仍有可独立完成而未完成的检查，不得宣称完整审核结束。确实缺材料时一次列齐缺项及受阻范围，同时完成其余检查。
每项确认缺陷给出严重程度、位置、触发/复现、实际影响、修复和验收标准。区分静态、本地、模拟集成、Hosted、真实浏览器、实机和生产验收；跳过/UNKNOWN不得算PASS，重叠测试不重复累计。
未变且已有有效通过证据直接继承，仅复审修复与实际受影响调用链。新增阻塞必须说明此前为何遗漏、是否新增代码引入及属于残留/回归/新发现；不能隐瞒真实新缺陷，也不能无证据扩大门禁。
结论写回原PR/Issue并回读；不能用换账号、换工具规避安全拒绝，不能用开发身份冒充独审。完整覆盖不等于保证发现所有潜在缺陷。

## 5. 部署试错、保留现场与升级

替代旧ONE_PERMIT_MAX_5_ATTEMPTS及另签安装许可流程。审核通过后在Owner既定范围内持续执行。
每次尝试使用唯一ID；持久记录任务/节点、准确版本/制品、开始结束时间、执行结果、日志摘要/位置、实际副作用、事务/恢复检查点、原因、调整和下一次验证方法。秘密与现场敏感原文私有保管，公开记录仅必要摘要及哈希。
失败后先可信对账，再调整和安全续接；已确认成功阶段不重跑。成功后停止试错并验收，不为凑次数执行。
每轮累计失败达到10次，或本轮实际工作达到1小时仍未完成，任一先到，必须暂停沿用当前失败方法，并向Dots集中报告失败现场、原因总结及证据，同时提出改变思路、改变方法的具体替代方案，不能只汇报后继续重复旧方法。Dots必须审核替代方法是否可行；可行则审核通过，并在受影响代码完成必要增量审核后继续实施，不另申请安装许可；不可行则Dots与ChatGPT执行负责人共同分析、制定另一种方法，直至形成可行方案后再继续。不得仅退回一句“不可行”而不协同解决，也不得为了继续执行将未证实方案写成通过。
同一节点/原任务累计失败达到30次，或累计实际工作达到5小时仍未完成，任一先到，停止新增部署尝试，集中报告Owner并等待裁定；在安全范围内保全证据及必要止损。
实际工作耗时含执行、诊断、修复和测试；等待Owner/外部依赖另记并保留墙钟时间。Dots通过替代方法可开启下一轮，任务累计数/时间不得清零；改名、换窗口、重启不能重置。启动即记尝试，中断/结果未知也须记录，不能通过重编号藏匿失败。
UNKNOWN、未确认部分写入、Writer/Lease/Fence冲突先HOLD对应操作并对账；无法证明安全续接不得盲试。平台安全拒绝立即停止该操作，不更换路径绕过。真实资金、新增敏感权限和不可逆越界操作不因本规则自动获准。

## 6. 连续执行与防止循环

汇报、计划、提交少量代码、交下一窗口都不能代替交付。没有真实阻塞不得停工等待Owner催促；每个节点持续到验收关闭或明确记录外部阻塞。
交付责任不随送审转移。Dots维护问题清单，执行负责人负责补齐；不让Owner来回传材料。现有通道能自动取得的证据由系统取得，不要求Owner重复提供。
每次退回必须指出新增证据、修复变化或验证结果；相同版本和相同证据不得无限循环退回。重复无进展按本文件升级处理，不再增加平行任务或审批层。
缺少尚未部署的组件，应明确NOT_DEPLOYED并形成准确实施工作，不能反复要求不存在的现场凭证。源码与新流程冲突时由执行负责人适配并测试，不能伪造批准或直接跳过真实保护。

## 7. 持久规则与交付完成检查

每次领取、重启、换窗口、恢复和送审前，重新读取根AGENTS.md、本文件及原任务清单；不得仅靠聊天记忆。
Dots在原任务记录本规则版本、当前节点、实例/Writer、准确版本、审核清单、试错账本、耗时及下一实际动作；沿用原PR/Issue/ledger，不创建平行项目。
最终证据包含Commit/Tree、文件/制品/Manifest绑定、CI Run/Job与实际终态、部署回执、功能验收、异常恢复及剩余依赖。未执行标NOT_EXECUTED，未证明标UNKNOWN。
“规则已写入”“自动门禁已实现”“已部署”“已验收”分别记录。只有确有执行证据才能声称持续运行；聊天结束不意味着存在后台执行器。
后续调度器/CI必须校验节点完整字段、审核范围完成度、身份隔离、版本绑定、失败计数/耗时、单Writer及完成证据。结构检查不能证明AI真的完成语义审核。未完成接线前由Dots按清单执行，不宣称已实现自动强制。

## 8. 原P自动化闭环的分工优化与接口接续

本节仅优化原P任务，不重新建设平台、队列、账本、调度器或平行审批系统。复用原任务PR17、已有P2/P3阶段、Canonical任务记录、事件、超时恢复、锁/Fence、检查点和已验证成果；原PR58作为历史审核证据继续引用。
新增接口先盘点实际最新版本，分类为“已有且复用／已有未接通／确需补齐／不支持／待验证”，不能据当前未看到就重建，也不能据源码存在就认定实机可用。

### 8.1 分工及四段接口

| 原链路接口 | 实际职责与必须回传的证据 |
| --- | --- |
| Dots → 开发执行器 | 创建、查询、停止任务，按独立小节点、依赖、资源与额度动态安排多个ChatGPT执行实例；记录实际运行ID、session和领取ACK |
| 开发执行器 → GitHub | 领取原任务、独立分支/工作区开发、提交准确Commit/Tree、运行并核验CI；交付负责人集成受影响调用链后送Dots集中审核 |
| GitHub → OpenClaw | 通过原受信通道领取准确任务、版本、制品/Manifest/SHA及Dots审核决定；机械校验并执行已授权范围部署，不增加独立安装许可 |
| OpenClaw → 原任务记录 | 回传实际运行ID、日志引用、退出状态、副作用、检查点和实机验收结果，产生下一事件；失败需要推理/改代码时交回对应ChatGPT执行者 |

ChatGPT承担开发与交付责任，OpenClaw承担服务器机械动作；不因ChatGPT只连接GitHub就假定它直接持有服务器会话。Work不接管上述产品执行链。
闭环顺序：Dots分派 → ChatGPT开发/测试/自检 → GitHub与CI → Dots审核 → OpenClaw部署/检查 → 回执事件 → ChatGPT必要修复与增量送审，或Dots核对实机结果关闭节点。
必须区分分派、接收、实际开始、持续进展和完成。评论成功、消息已发、ACK或工具退出0均不能独自替代功能验收。失败不让Owner反复传话，沿原任务和事件链续接。

### 8.2 零模型API调用目标及原生会话适配器

不强制引入模型API。优先核验并复用原生Gateway、会话执行器及OpenClaw已有获准入口；只有实际支持的启动/续接能力才能登记可用，不能凭“适配器”名称虚构普通网页聊天窗口唤醒接口。

### 8.3 两类时限分别处理

- 原5分钟：未接收时恢复接收/重新扫描。
- 原10分钟：未启动或无进展时检查原Writer，符合条件才续接。
- 原15分钟：满足原Writer停止、同Attempt和旧Fence失效等条件才受控恢复，否则HOLD。
- 上述5/10/15分钟是原版本停滞检测机制，不是安装许可有效期，也不取代第5节失败升级规则。
- 每轮10次失败或1小时仍未完成，任一先到，须报告Dots并提出改变思路、改变方法的具体方案；Dots审核可行性，可行则通过并增量审核受影响代码后实施，不可行则与执行负责人共同制定另一方案；累计30次或5小时仍未完成，任一先到报告Owner。失败次数和耗时跨方法、会话与重启持久累计。
- UNKNOWN不能直接重发；先对账，证明无重复副作用后续接。已完成阶段不重跑。需要改代码时先增量审核，不重审未变部分。
