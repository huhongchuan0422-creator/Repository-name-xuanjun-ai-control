# 玄钧平台用户与定制项目终端用户隔离规则

状态：OWNER_RULE_REGISTERED / IMPLEMENTATION_PENDING。适用全部既有和未来定制项目。复用原Identity/Tenant/Customer/Project/CRM/RBAC、渠道身份关联、私有SecretRef能力，不建立平行平台CRM。

## 两套身份边界
A. 玄钧云汇平台用户：统一平台customer_id，是服务购买者、定制委托者及其授权平台项目成员；平台Telegram、用户飞书、网站AI三入口关联该平台customer_id，推荐关系由平台原归因账本控制。
B. 定制项目终端用户：由各项目独立命名空间管理，如(project_id, project_user_id)，包含社区分账商户、消费者、社区管理员及分账接收者；不能因为登录项目就被自动创建为玄钧平台Customer，也不能使用平台推荐人关系或平台客户权限。项目可以复用身份、消息、角色、注册代码组件，但必须独立数据作用域、隐私政策、主体、审批、存储及通知渠道配置。

## 授权与交叉身份
同一个现实自然人或企业可以分别拥有平台账号及多个项目终端身份，默认隔离；确有跨域管理需要时，经服务端认证、合法目的、明确授权、项目Owner批准（按风险）、最小字段映射和审计，建立单独的跨域关联映射表，不合并账号或覆盖用户主键。项目终端用户不得浏览玄钧平台订单、合同、密钥、CRM；平台员工亦不得因管理平台而默认获取所有定制项目终端个人信息。服务运营主体和个人信息处理者按具体项目合同和实际职责确定。

## 项目资料与凭据
平台客户作为原定制委托者，经customer_id+contract/project权限验证后管理合同资料、项目交付密钥与授权，沿用 CUSTOMER_SECRET_PORTAL_ROTATION_V1_20261016.md。项目终端用户的API授权及个人资料，走项目内获准角色/专属SecretRef命名空间与隐私规则；如业务确实允许商户自行更新支付或第三方密钥，必须核验商户/门店/项目归属和额外支付风险权限，禁止任何终端用户修改平台主密钥、其他商家密钥或平台客户开发合同。原密钥保持直到新版本验证、审批及原子切换完成，异常进入HOLD/UNKNOWN。

## 三渠道与推荐
用户飞书、Telegram、网站AI在“玄钧平台客户服务”域绑定一个平台customer_id。在“定制项目用户客服”域则使用项目project_user_id，并隔离机器人/app_id、会话、通知授权、客服知识库和数据记录；若同一机器人承载多个业务，服务端仍必须强制验证scope、project_id及业务角色。平台referral_code转发只归因平台客户注册/合规订单；项目自有推荐体系需项目Owner单独明确启用及授权，不自动共享平台推荐收益。

## 集成验收
1. 平台Customer与项目User的ID在不同命名空间；项目新注册不自动创建平台Customer。
2. 同一人持有两套身份时未经授权不能跨系统查看、修改合同、订单或凭据。
3. 社区分账商户A不可读取商户B、其他项目或平台密钥。
4. 项目终端用户三个渠道仅关联对应项目身份；不串消息、CRM及平台推荐关系。
5. 项目主体/隐私合同不同，按租户和项目落实合法告知、权限、审计及删除/保留策略。
6. 用户登录、绑定、解绑、撤权、密钥轮换、推荐转发和异常状态均覆盖负向测试。
