# 定制项目逐页反馈、整改评估与费用明细（强制规则）

沿用 PR122、统一账号、项目权限、加密数据库及审计日志，不建立重复客户体系。

只有该定制项目的客户OWNER登录、具有项目权限且匹配服务端获审预览记录后，每个私有预览页面底部才提供整改意见入口。VIEWER、EDITOR、REVIEWER及其他客户不能代为提交。意见绑定项目、页面路径、准确页面SHA256、获审Manifest、登录提交人和服务端时间。公共演示不收集私有资料、凭据或密钥。网页、Telegram、飞书将来均归档到同一项目；本次仅新增网页业务接口，不声称三渠道整改已接通。

先评估整个变更的实现、相关角色、数据、测试、部署及工期影响，再决定整改方式。没有统一工时或金额阈值时不得自行编造“小改”阈值；以项目合同约定及有权限的评估者结论为准。AI可辅助评估，不得自行收款、承诺免费范围或替客户确认。

1. 我方未达到已确认范围或验收标准的缺陷：我方免费修复，不能转为客户追加费用。
2. 合同内、评估工作量较小的调整：记录评估和免费明细后准入。
3. 较大调整：核对是否改变客户之前明确确认的需求。必须展示此前需求原文、确认主体、时间、版本及证据哈希。仅上传文件或开发人员自称“客户要求”不足以证明客户确认。
4. 原记录确为客户确认且本次改变原范围：说明差异、影响及新增费用；客户可保留原方案、确认收费变更或提出异议。不得强迫付费。
5. 证据不足或责任不明：NEEDS_EVIDENCE，不能归责、不能收费或自动执行。
6. 新增范围：原整改请求默认RECTIFICATION，审核员不能仅选择NEW_SCOPE就收费。真正独立新增功能须由客户明确选择NEW_ORDER提交独立请求；权威新订单/需求确认来源绑定该请求的唯一服务端事件ID和完整正文哈希、客户确认主体、文档及版本SHA、独立订单引用。客户登录再次确认该准确新需求后，才可由评估者提出逐项双币报价，之后客户还须单独确认报价。没有上述证据则NEEDS_EVIDENCE。客户点击确认不执行支付，收款仍须已审核订单服务。

项目预览与验收入口旁显示“整改费用明细”：意见、分类、评估说明、预计工作量、各项人民币/美元费用、合计、免费项、原确认记录及状态。不得公开内部成本或其他客户信息；税费、第三方费用、部署维护及工期影响应在正式报价前列清，UNKNOWN不得当作0。

实现：pr122_customer_changes.py 使用现有 Center 项目授权、AES-GCM 与追加审计；change_events为追加事件表。baseline接口只接受权威document_id，不能输入任意文本。原合同/需求确认单/已验收版本必须有准确原始文档、版本SHA、确认主体/时间及不可变来源引用；原文和完整签名来源保存在加密追加历史中。原基线必须在请求前已经登记，事后补录不自动成为历史合同。评估只允许REVIEWER，费用确认只允许OWNER。

服务端通过pr122_customer_change_authority.py导入受保护权威快照，purpose=PR122_CHANGE_AUTHORITY_V1，绑定当前项目授权revision、合同引用、已审核预览Manifest哈希、源码commit、制品SHA、审核回执引用及实际页面字节SHA。合同来源记录绑定准确客户/合同/文档版本。签名、有效期、单调revision、完整快照撤销均校验；客户端合法SHA格式不构成页面身份。提交、页脚生成、评估及确认都复核；提交事务内再次验证，防止检查到落库之间撤销。

import-change-authority是现有受保护operator工具中的新数据导入动作，不暴露HTTP写入口，也不自动获得原固定root通道权限。签发源必须来自已审核发布制品及真实合同/需求/订单确认系统，密钥由受保护配置提供；禁止用作者或客户手工填写的正文替代真实来源。目标机尚无该权威源接线与新动作许可，本候选仍HOLD，不得手工造生产签名fixture来放行。单元/浏览器使用的合成签名源只存在tests目录，未作为生产证据。

每次反馈和取证只读本地签名快照/数据库，不为每页调用AI或外部资料API。只有来源更新时机械导入一次，避免重复API消耗。历史已确认状态不等于后续执行或收款许可，未来执行端仍必须复核当前来源和授权。

当前交付为新增业务源码、客户中心明细界面及通用私有预览页脚组件。真实私有预览渲染器调用、AI工作量网关、权威报价、订单收款、三渠道整改、生产部署须分别取得实际证据；当前均未开放。客户中心生产安装、真实资料和密钥入口原HOLD继续有效。
