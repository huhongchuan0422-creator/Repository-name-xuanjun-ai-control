# 玄钧AI新统一管理后台：冻结设计基线 V1

> 状态：`OWNER_CONFIRMED / FROZEN_BASELINE_V1`
>
> 冻结来源：`adb1677e163eafa57c17902ad3e91e700bf1be81`；三点修正版由后继 Commit 固定。
>
> Owner确认时间：2026-10-30。本基线只确认统一后台框架与视觉，不代表正式认证、业务接线、部署或客户验收。

## 1. 设计目标

- 专业、可信、克制；复杂业务分组、分步和按需展开，不用整页技术表单。
- 先呈现任务、阶段、责任、风险和下一动作，再展开技术证据。
- UI永远区分候选、源码、测试、安装和验收。
- 桌面保持高信息密度，手机保持主动作可达和单列可读。

Owner于2026-10-30提供后台参考图。本候选吸收其左侧分组导航、顶部上下文栏、
浅灰画布、白色指标卡、二级页签与筛选工具条；不复制返佣业务、品牌标识、图标、
具体文案或页面DOM。玄钧页面仍以项目、审核、证据、权限和UNKNOWN为主线。

## 3. 布局

- 桌面：252px可折叠二级侧栏 + 68px顶栏 + 最大1440px内容区；详情/审核工作区可用三栏。
- 平板：1120px以下指标/事实网格降列；820px以下进入移动外壳。
- 手机：顶部菜单打开同一十一项一级/二级侧栏，底部保留五个核心入口；单列内容、底部固定主要审核动作；表格横向可控滚动。
- 面包屑始终表达 `业务域 > 项目 > 页面/任务`。

## 4. 核心组件

- `AppShell`、`SideNav`、`TopBar`、`Breadcrumbs`。
- `SideNav`：总览、运营、客户、研发、验收交付、维护、共享生态、财务、自营业务、预览审核、配置十一项一级入口及其二级项；父项展开/收起，详情深链同时高亮所属父域与子项。
- `StatusBadge`：状态颜色不能单独承载语义，必须有文字/图标。
- `MetricCard`、`ProjectCard`、`EvidenceCard`、`RiskBanner`。
- `DataTable`：筛选、排序、空态、零结果、加载、失败、权限不足分离。
- `DetailHeader`：名称、版本、环境、责任人、真实状态、动作。
- `StepRail`：需求→原型/UI→开发→测试→安装→验收；不是tab。
- `Tabs`：只用于互斥详情，最多7个。
- `Drawer`：快速预览/轻量筛选；复杂审核进入完整页面。
- `ReviewWorkspace`：页面树、预览画布、审核面板；移动端依次折叠。
- `VersionCompare`：基线、候选、差异、影响页面和证据。
- `PermissionNotice`、`NotConnectedState`、`ConflictState`。

## 5. 交互模式

- 登录仅账号、密码、登录按钮及状态说明；复用已有认证，不新增验证码/身份体系。
- 候选登录与后台必须严格互斥，`[hidden]` 不得被组件样式覆盖；候选仅用标签页级演示状态验证刷新/退出，不构成正式会话。
- 列表点击进入详情；“快速查看”可用抽屉，但不嵌套抽屉。
- 长资料分“摘要—步骤—证据—高级信息”，默认只展示当前任务需要的信息。
- 审核意见先保存草稿，再由原服务提交；候选界面仅演示状态，不伪造落账。
- 版本冲突必须显示当前基线、提交版本、影响范围和刷新/返回选项，不静默覆盖。
- 未接入状态给出事实生产者、缺项和责任方，而不是空白或假数据。

## 6. 空态和异常态

- `EMPTY`：数据源已连接但当前无记录。
- `ZERO_RESULT`：筛选无匹配，可清除筛选。
- `LOADING`：骨架屏并保留页面结构。
- `FAILED`：显示请求标识、可重试/返回，不暴露内部异常或密钥。
- `FORBIDDEN`：说明无权查看，不泄露资源是否存在。
- `VERSION_CONFLICT`：阻止覆盖并要求重新基于当前版本。
- `NOT_CONNECTED/UNKNOWN`：显示未接生产者、不可执行动作和下一责任方。

## 7. 模块扩展契约

- 路由：`/workbench/{domain}/{resource}/{id?}`；预览审核使用项目、页面和版本选择器，不以裸URL作为主键。
- 权限：前端消费服务端返回的能力集合；隐藏按钮不替代服务端RBAC。
- 页面模板：列表、详情、工作区、设置四类；新增模块优先组合现有模板和组件。
- 数据接口：UI只读取原权威投影；写操作回原服务鉴权、幂等和留痕。
- 新功能不得改变全局导航、品牌token或公共交互；如需改基线，先提交原因、影响范围和新旧对比。
- 每次扩展回归登录、导航、返回、权限、旧入口、响应式和已有模块。
