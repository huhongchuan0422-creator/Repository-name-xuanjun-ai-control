# PR122 验收功能自动生成与角色隔离整改

责任：Work 生成器、集成包装与展示验收。沿用 PR122 和原 Work 分支。

原机制只发现已审核的整页；此前公开体验叠加了跨角色导航与设备切换壳，不满足客户体验要求。原62项生产检查仅代表所列技术检查通过，不代表视觉及商业体验合格。

本增量增加 feature 声明：role、device、milestone_id、page_id、page_version、page_artifact_sha256。声明本身必须经现有独立信任验证；项目必须公开获审，里程碑必须 DONE，页面必须获审并有准确制品绑定。作者填写 DONE 或增加页面都不能单独放行。

上述条件只是必要条件，不等于验收通过。还必须提供独立核验的 feature_acceptance 声明：project_version、snapshot_sha256、完整 members、feature_sha256 与 evidence_url。现有受保护审核信任链校验该声明的准确对象哈希；构建器再校验同项目当前版本、当前项目/页面/里程碑快照及完整成员集合、准确功能哈希。缺少记录、旧版本、跨项目、成员不匹配或审核撤销均拒绝生成。

本合同允许单个功能先于项目整体完成独立验收并公开；但只有获审 DONE 不足以构成功能验收。功能级验收不将项目转为成熟案例，整体验收仍沿用原 acceptance 全项目合同。只有 feature_acceptance 完整有效后，构建器才自动生成 projects/{project}/roles/{role}/{device}/ 页面、项目角色入口及角色内部功能导航。无需编写角色索引HTML。存在功能合同但没有通过验收的功能时，禁止回退到旧整页链接绕过功能门禁。消费者及商家采用 phone；平台与网站管理可分别声明 phone/desktop。不同角色不会共享功能导航。

生成器负责组织已获审功能，不凭功能名称虚构业务实现。进入功能仍调用准确获审实现；原作者实现中存在跨角色内容时须在内容验收时拒绝，不能因生成器已隔离索引就声称底层实现全部合格。

本轮同时移除 Work 手机包装器注入的角色切换条、设备切换按钮及模拟手机外框；各角色仅保留返回项目。平台按响应式电脑后台布局适配手机。原业务引擎和内部测试页不覆盖。

首轮82项Hosted报告实际为45执行通过、37跳过，原“82项全部PASS”表述撤回。此次新增8个测试方法（含参数化拒绝子案例）；验收用例必须提供真实 feature_acceptance。Hosted生成器工作流改用临时root测试环境执行权限相关用例，并输出total/executed/passed/skipped/failures/errors。出现任何跳过即不满足该工作流完整通过要求。不能用本地root结果替代Hosted结果。

发布仍必须更新机制制品、独立审核、生产信任登记、准确目标Plan及新许可。旧单次发布许可不得复用。本增量不表示动态机制已安装，也不表示现网已整改。
