# 玄钧云汇阿里云自动选购、采购、部署与运维 V1

Owner需求：从客户提出服务器需求、AI选型、供应商实时询价、双币报价、合同及真实付款、阿里云采购、软件安装部署、验收交付、监控续费和财务核销，全流程按预先授权自动运转。目标TARGET，不代表真实Aliyun已连接。本任务是现有全自动经营闭环的采购模块，不新增第二套CRM/Finance/Procurement/SecretRef/任务调度。

## 一、账户接入与职责
优先使用阿里云RAM角色、STS临时凭据与最小权限；禁止把阿里云主账号密码、主账号AK或客户秘钥发送到聊天、公开GitHub、飞书或Telegram。客户自购模式使用其客户阿里云账户授予的跨账号RAM角色，资源归客户账户；玄钧代购模式必须确认经销/代理身份、正式付款方、合同责任及供应商账单、税务。授权按资源、地域、操作、预算和有效期分离，绝不使用全局AdministratorAccess实现快捷上线。
只读资源顾问角色负责规格、价格、库存、当前实例状况与成本；受控采购角色仅在真实付款、现行Price Book、客户确认的订单预算及策略范围内创建指定资源；受控部署角色仅对该项目的新购或明确授权的服务器运行预审模板，不得触碰其他客户资源。设置STS/账号授权到期和撤销机制、异常限制、凭据轮换、访问审计与职责冲突检验。每个客户云账号独立存储授权引用，并绑定项目身份和商业合同。

## 二、业务流程及操作门禁
LEAD_CONFIRMED → REQUIREMENTS_READY → PRICE_CHECKED → QUOTE_APPROVED_BY_POLICY → CUSTOMER_ACCEPTED → PAYMENT_VERIFIED → PURCHASE_READY → PURCHASE_SUBMITTED → PROVIDER_CONFIRMED → DEPLOYED → SECURITY_TESTED → CUSTOMER_ACCEPTED_DELIVERY → ACTIVE_MONITORING → RENEWAL_OR_EXIT → FINANCE_RECONCILED。
具体规格包括地域、CPU、内存、系统盘、带宽、系统镜像、计费方式、可用区、数据保留、合规地区与预期月费。ECS在线价格和可用库存以供应商OpenAPI有效回执为准；不编造折扣或库存。报价区分官方/供应商价格、代购服务费、部署费、维护费、税费、两币报价与实际支付币种，复用现有Price Book与Finance政策；阿里云服务器原既定返利22%毛返点、税点6.72%及净约20.52%只是Owner历史商业口径，必须以真实经销协议/订单价格核验，不将其当所有客户或所有SKU的保证收益。低于2.9折不参与的历史商业限制继续作为待验证定价门禁。
客户付款必须真实支付通道服务端验签后才能调用购买动作，不得用浏览器跳转/截图判定已付款。创建ECS等昂贵有副作用操作必须有canonical operation_id、预算上限、幂等键/订单关联；响应丢失或UNKNOWN先查供应商订单/实例，不盲目重购。购买后使用阿里云ROS/IaC和运维模板受控部署，签名制品、扫描、最小权限、网络安全组、备份、监控、预览/变更审计及可恢复回滚；商用部署应符合供应商资质、实名/备案要求。
付款或折扣规则未知、账户授权失效、跨区域不合规、项目权限不足、变更/成本UNKNOWN、密钥获取不符合规范、额度可能超限、实例非目标项目、系统审查失败均HOLD。不得由于Owner希望日常零介入而自行伪造客户同意、独立安全审批或支付凭据。

## 三、自动化执行权限与验收
英国GitHub/OpenClaw控制面只根据已批准任务、供应商事件和状态账本触发确定性动作；国内CRM、客户登录、报价、订单及支付依旧按既有归属处理，客户云账户必须与项目严格隔离。控制面不得接收长期AK明文；由受信任的凭据代理签发短期STS，留角色/调用/客户/项目/供应商资源ID/审计回执。
首先只读对接已有阿里云账号，查询可调用的权限、ECS列表、账单/价格能力及ROS部署条件；独立审核后才能逐步启用沙盒创建、低预算受控创建、真实自动部署和批量客户订单。至少测试：跨客户访问拒绝、虚假付款拒绝、重复点击/网络超时不双购、创建后响应丢失能对账、错误地域/规格/预算阻断、异常云服务费防超限、STS过期与撤销、并发下单、部分创建与回滚、真实主机安装后验证、备份恢复、合同/账单/供应商收据对账。
自动选型与推荐是可标准化决策；付款、真实云资源采购、税务及客户确认是受限经济行为，必须由明确合同及已批准商业和风险政策授权。无任何真实阿里云凭据或实际已连接证据时，记 ALIYUN_ACCOUNT_CONNECTED=UNKNOWN、READ_ONLY_VERIFIED=NO、PURCHASE_ENABLED=NO、PRODUCTION_DEPLOYED=NO。

## 四、首批具体实施
1. Owner在阿里云主账号中自行安全建立限定权限的RAM角色及MFA，不提供主账号密码或长期主账号AK；角色用于受控执行器，非聊天模型。
2. 复用现有客户中心的「凭据与授权」页面，提供阿里云账号绑定/跨账号RAM角色授权、授权权限/到期状态、撤权入口和操作审计；客户可以分批准备企业认证/备案材料。
3. 英国只读Runner使用受控短期凭据核验账号及资源，先拿真实回执，再由开发方完善ECS选型与报价、ROS模板、成本/归属合同、支付采购对账、部署运维各增量。
4. 明确何种订单由客户账户自行支付，何种订单由玄钧合法代购；该选择影响税票、返利、营收归属和资源所有权。未取得真实结算授权不得开展真实购买。
