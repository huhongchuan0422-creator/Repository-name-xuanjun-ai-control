# 定制项目功能/页面验收争议自动溯源 V1

Owner要求：客户在预览验收版本对某个功能或页面提出调整时，玄钧AI应自动找出是否曾有相关需求、报价、AI客服解释、客户确认、设计稿、合同任务书、变更单、历史验收及实际交付证据，而不是笼统引用整份合同、让客户与平台争论。状态 OWNER_RULE_REGISTERED / IMPLEMENTATION_PENDING / PRODUCTION_HOLD。沿用原PR122 CRM/Project/Contract/Quote/Change/Acceptance/Web3私有证据账本，不建平行数据主库。

## 精确功能绑定
每个页面或功能在最初需求阶段分配不可重复的 feature_id，页面具备 route_id、project_id、tenant_id、版本、关联模块ID和有权限的客户身份。合同任务书的每一交付项绑定 feature_id、描述、验收标准、边界/排除项、交付版本、有效选择与报价快照、双方授权确认、承诺过的性能与UI约定、所需认证/API/第三方依赖。客户的聊天、点击、附件、原型截图、反馈和版本评论以明确关联引用连接 feature_id，并保留来源和可信时间。历史版本不可静默覆盖。

## 客户调整与争议处理
客户在预览页面点击“提出修改”时，系统记录 project_id、feature_id、release_id、页面route、截图/标注（需合法授权）、当前问题、客户期望、消息上下文。AI先在该项目获授权的私有合同和客户会话中检索与该功能相关的精确版本证据；按有效合同、任务书、后续获双方确认变更单和客户明确承诺的适用性，区分：
A 已约定功能但未实现、质量缺陷、与已签设计不一致：进入原范围修复，不得默认另收费；
B 已约定且实现符合标准，客户提出新增能力/设计风格/不同方案：生成变更建议，明示增量费用、工期、影响，客户明确确认后执行；
C 原约定不明确、聊天表述存在歧义、证据缺失或冲突：标记 DISPUTED/NEEDS_HUMAN_REVIEW，不得让AI单方判定客户无理或自动收费；可提出双方协商和可选方案。

系统在客户页面展示该争议的“相关约定”摘要、具体合同附件条目与版本、双方确认记录、关联聊天/原型及测试证据；客户可以查看其有权访问的原文并提出反证，不能用AI摘要代替原始材料，也不得泄露其他客户/商家的聊天。禁止仅凭相似文字匹配将不相干的承诺归因到该feature_id。

## Web3存证和财务联动
私有账本以append-only事件保存客户请求、平台答复、相关条款哈希、AI检索依据、裁定与实际修复/变更结果；公开Web3仅提交经隐私设计的批次证明，不公开聊天原文、合同、密钥、客户ID。每次变更经版本化报价与有权代表确认后才能改变价格或交期；已确认合同、项目交付和账单不得被新事件追溯覆盖。平台依法应承担的缺陷修复责任不得通过格式条款或系统默认选择转嫁客户。

## 强制验收
1. 项目A页面/功能X有明确合同验收标准，交付不符→正确匹配条款、归类原约定缺陷、不收费。
2. 功能X满足标准，客户要求新增字段或新页面→标记候选变更并出具费用/工期，未经客户确认不执行或收费。
3. 旧聊天曾有相关承诺但未进入合同/变更，系统同时展示对话及合同版本，不武断忽略或认定自动生效，交有权人员处理。
4. 合同条款不明、历史约定互相冲突、客户质疑AI判断→支持申诉/补证/独立复核，不得阻断法定权利。
5. 多项目并行时同名功能不串证据，跨项目/租户/页面访问拒绝。
6. 客户逐轮查看预览、调整、反馈后，旧版和最终验收版本证据可追溯；未取得真实证据的项UNKNOWN，不能伪称满足。
7. Web3完整私有证据与公开匿名承诺分离，客户仅能导出其有权访问的内容；记录撤回、删除请求按法律及数据治理流程处理。

客户体验目标：在页面选择“查看相关约定”，几秒内显示“约定内容／当时谁确认／当前交付与约定差异／建议下一步”；但查询响应时间为产品目标，未实测不宣称达标。正式代码与合同条款必须经独立审核和真实浏览器/权限测试后才能上线。
