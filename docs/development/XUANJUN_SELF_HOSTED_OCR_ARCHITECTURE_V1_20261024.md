# 玄钧AI新｜自建OCR与商家证照智能识别开发规范 V1.0

> 日期：2026-10-24｜状态：架构需求已确定，代码与线上验收未完成。
> 归属：通用 AI 能力 / 商家入驻 / SaaS 可复用模块。
> 原始业务承接：社区 Issue #76。**本文件不是对现有 Issue #76 唯一源码 Writer 的改派，不授权其外人员修改既有入驻源码。**

## 1. 决策与边界
- **确定自建 OCR 能力**：优先采用成熟、许可经核实可用的开源预训练模型（候选 PaddleOCR），不从零训练 OCR 基础模型。
- 统一开发自有 `OCR Gateway`、证件分类、字段映射、质量检测、审核交接及指标体系，后续可作为玄钧AI新 SaaS 独立计费模块。
- 默认本地推理，云 OCR 仅作为可配置的可选后备引擎；后备调用必须有数据传输合法性、授权和成本开关，不得私自传输证件影像。
- **OCR 只识别文字，不等于证照真实性验证**；微信支付服务商商户进件及特约商户状态仍走真实官方流程。商家需通过本服务商申请微信支付，不建立“绑定已有商户号”入口。
- 不修改币安生产/英国 P2/官网导航；部署隔离，绝不与交易执行共享资源配额。
- 任务必须复用已完成的 UI、服务端字段规则、上传控件与测试；已有通过且未变的证据不重复验收。

## 2. 第一批范围与优先级
- P0：营业执照（主体名称、统一社会信用代码、法定代表人、经营场所、经营范围、营业期限等，依图片实际出现字段提取）；身份证正反面（姓名、证号、住址、有效期等）；银行卡/开户信息可识别字段。对不确定、缺失字段返回空值，不臆造。
- P1：食品经营许可证及其他行业许可、门店相关证照；版本化扩展字段字典，避免为每种证件硬编码全站。
- P2：通用票据与非标准表单、跨语言及批量文档，独立评估后开发。
- **银行卡 OCR 不代表卡主实名核验，身份证 OCR 不代表公安实名核验；开户许可证据和微信结算账户字段不可混同。**

## 3. 业务体验（与 Issue #76 原需求对齐）
1. 用户选择主体类型和经营场景后，立即展示当前适用的上传框，不能等下一阶段字段填完才显示。
2. 先上传图片 -> 图片安全检查/质量提示 -> OCR -> 对应字段自动填入 -> 用户逐项核对和修改 -> 保存草稿或提交。
3. OCR 超时、模型不支持、低置信度或服务不可用时，提供手动填写；**OCR 失败不得成为入驻阻塞条件**（法律/微信业务本来必填的材料除外）。
4. 企业执照、个体工商户、个人及纯小程序/线下/混合场景使用同一版本的字段与必填规则。非微信真实必需附件不得由于 OCR 接入变为强制。
5. 原生微信小程序和商家预览在字段、状态、校验、提示与返回结果上保持一致；平台管理端保留原件及人工审核入口。
6. 用户确认后的字段与 OCR 原始建议分开存储；后续 OCR 重试不可覆盖人工修正值。

## 4. 参考架构
```text
原生小程序 / Web商家后台 / 未来SaaS客户端
          -> 现有身份与租户校验 -> 文件上传/对象存储
          -> OCR Gateway (鉴权、队列、限流、幂等、审计)
          -> 图片防护及预处理 (类型、大小、解码、去畸变、质量)
          -> 文档分类 -> 本地 OCR 推理 -> 版式字段映射
          -> 置信度/规则校验 -> 用户校对 -> 入驻数据/平台审核
                           \-> 可选云OCR后备（默认禁用）
```
- OCR Worker 与业务 API 分进程/容器，按资源限额调度；支持 CPU 起步和按负载升级 GPU。
- 预训练模型与 Python 依赖必须固定准确版本、来源、许可证、模型文件 SHA256；离线可安装，禁止运行时无控制下载。
- 服务端强制租户隔离和角色授权，禁止跨租户读取影像、OCR 文本、审计记录。
- 不把完整身份证号、银行卡号、证照影像写入日志、错误追踪、指标或 GitHub；使用字段级脱敏、传输加密、存储加密、受控清理周期。
- 若云后备打开，应记录引擎、地域、数据流向、用户告知/授权、费用上限，未满足条件则 fail closed 到手填。

## 5. 接口草案（新增独立命名空间，最终与现有系统路由核对）
- `POST /api/v1/ocr/jobs`: multipart/受控文件引用 + `document_type_hint` + `onboarding_application_id` + `idempotency_key`；返回 `job_id,status=queued`。
- `GET /api/v1/ocr/jobs/{job_id}`: 状态 `queued|processing|succeeded|needs_review|failed`、`document_type`、`fields`、`warnings`、`model_version`；字段附 `value`、`confidence`、`source_bbox`（适用时）。
- `POST /api/v1/ocr/jobs/{job_id}/confirm`: 提交用户确认/修改的字段；重放幂等、不覆盖既有人工确认。
- `POST /api/v1/ocr/jobs/{job_id}/cancel`: 有权用户取消待执行任务；执行中明确状态约束。
- 输入校验：大小、MIME+魔数、解码、页数/像素上限、防压缩炸弹；不可解析图片返回明确错误码。
- 网关使用现有身份令牌、归属、权限和审计设施，不额外发明第二套客户ID/推荐关系。

## 6. 数据模型与状态
- `ocr_job`: job_id, tenant_id, actor_id, onboarding_id, document_type_hint/detected, state, source_object_ref, engine/model_version, attempt_count, timestamps, error_code。
- `ocr_field`: job_id, field_key, suggested_value(加密/受控), confidence, bbox, validator_result, schema_version。
- `ocr_confirmation`: job_id, actor_id, confirmed_payload(加密/受控), revision, confirmed_at；保留修改来源，不以重跑结果覆盖。
- 去重键至少绑定 tenant + application + attachment_sha256 + schema/model版本 + idempotency_key；竞态和重投安全。
- 文件与识别结果保存期限依实际业务和法律要求配置，不默认永久保留；删除申请要覆盖对象、索引、缓存和备份生命周期策略。

## 7. 实施顺序与唯一 Writer
1. 只读盘点 Issue #76 现有上传、字段定义、审批及相关测试，产出映射表；不新建与原系统竞争的入驻入口。
2. 建 OCR 模块的独立目录、模型锁定文件、可复现环境、纯离线健康检查及测试夹具（测试证件采用合成/已授权且脱敏材料）。
3. 开发 Gateway、隔离 Worker、结构化解析、错误返回、保密审计、幂等与负载限制。
4. 对照真实入驻字段契约集成小程序/Web；**只有原 Issue #76 唯一源码 Writer 或明确交接后的唯一 Writer 能落入驻源码更改**。
5. 离线集成测试与 Hosted CI 全部通过后提交 PR；先灰度后生产，生产需独立部署批准。

## 8. 一次性交付验收门槛
- 功能：营业执照及身份证双面含字段映射、用户核对、草稿保存和平台复核；模糊/旋转/反光/遮挡/过期/非证照/错误类型均能显式报低置信度或失败，不伪造成功。
- 一致性：原生小程序、Web、后端必填字段及场景规则一致；先上传再核对；不因 OCR 失败禁止手填。
- 安全：未授权/跨租户/越权/重放/并发/恶意图片/超大文件/日志泄露均有测试；不传第三方除非明确授权。
- 性能：在目标部署机器和代表性样本集上实测 P50/P95、CPU/RAM、队列深度、失败率、每千次成本；**没有实测不承诺识别准确率、耗时或处理能力**。
- 识别质量：按文档类型定义字段级准确率、关键字段人工复核率和失败率；固定样本集、记录模型及数据版本，结果可复现，阈值经真实业务验证确定。
- 交付证据：变更文件清单、Commit/Tree SHA、锁定模型及许可证、测试清单与 CI Run ID、样本统计、部署/回滚步骤、外部依赖 UNKNOWN 表。不得以绿灯代替真实微信进件或证照核验。
- 状态：文档登记后仍为 `DESIGN_READY / NOT_IMPLEMENTED / NOT_DEPLOYED`，直到真实回执证明下一状态。

## 9. 成本记录（采购决策，不将估算当报价）
按月记录自建固定成本（服务器/存储/维护/模型更新）、变量成本（计算/带宽/人工纠错）及可选云调用费用；设置云后备月度费用硬上限，记录每千张成本。达到实际负载再决定是否采购专属推理服务器。

## 10. 外部依赖
- 待原入驻 Writer 确认当前字段契约与页面接口。
- 待管理员确认脱敏数据保留周期与是否允许第三方云 OCR 后备。
- 待取得目标隔离计算资源的只读容量数据。
- 微信服务商进件、证件真实性核验属于独立外部依赖，不可由 OCR 成功代替。
