# 统一管理后台多平台模型接入：现状与缺口（2026-10-31）

## 同版现有能力

- `provider_onboarding.py` 已固定支持硅基流动、OpenAI API、DeepSeek API、阿里云百炼兼容模式；OpenAI、DeepSeek、百炼复用既有 `openai-compatible` 协议适配，不新增平台专用框架。
- 平台目的地址由服务端预设固定，前端不能提交任意 `base_url`。
- 既有服务端动作覆盖连接测试、模型目录发现、最多一次请求/最多 2 个输出 token 的显式模型调用验证、保存连接和模型、停用 Provider。
- 凭据由 `ConnectionManager` 加密保存；统一后台投影只返回配置状态和 `SecretRef`，不返回 mask、cipher、token 或 Key。
- 既有 ModelControl 已有模型清单、OpenAI 通道偏好、任务/attempt/角色绑定和用量/估算成本记录。

## 本次补齐

- 统一后台服务端投影增加经过白名单归一化的平台预设、onboarding 状态、受保护连接、模型清单和任务绑定。
- `配置 → 大模型` 增加同一后台内的卡片式平台选择与三步短流程：连接测试/模型发现、显式单次调用验证、保存连接与模型。
- 前端只调用既有 `/api/admin/model-control` 动作；服务端继续重验管理员身份、CSRF、固定平台、凭据和同一测试回执。
- 凭据输入为临时 password 字段，不写 fixture、日志、URL、localStorage 或 sessionStorage；保存成功立即清空。
- 客户购买/配置功能模块仍属于官网流程；未新增客户后台页、第二套后台或官网代码变更。

## 准确未闭合项

- 当前运行实例的 SQLite 父目录受 root 保护；本 Writer 无权读取真实 registry/config。OpenAI、硅基流动等平台在现场是否已配置、当前版本和当前绑定均为 `UNKNOWN`，不得由候选 fixture 推断。
- 本次仅形成未部署 UI/投影候选。真实安装前需由现有受控入口提供脱敏的当前配置投影，并走独立 QA/安全审核；不得读取或输出密钥。
- 新增或替换任何持久凭据仍需在现有管理员登录与安全确认点执行。本候选没有新增 sudo、凭据或权限。
- 真实连接/调用测试会产生外部效果；必须由管理员明确输入凭据并对单次付费测试勾选确认。未执行即不得报连接或模型可用。
