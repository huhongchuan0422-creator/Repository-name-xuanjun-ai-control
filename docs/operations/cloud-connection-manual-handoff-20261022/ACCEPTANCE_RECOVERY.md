# 验收、失败现场与恢复

## 每阶段非秘密回执
记录task=PR17、source=0177d391、Manifest/配置SHA、固定host/instance、执行人身份、真实UTC、唯一operation/Attempt、阶段、原调用ID、退出码、开始/完成状态、已确认副作用、未确认项及证据SHA。Workbench人工动作没有InvokeId就写NOT_APPLICABLE并记录真实操作ID，不能伪造云InvokeId。
秘密只保管在原获准保护位置；回执使用secret引用和是否具备，不给秘密本身。服务日志只投影错误码/状态，不贴request/token/客户资料或数据库正文。

## 必须停止且保留的情况
错主机/身份/版本/SHA、目标或状态来历不明、依赖/补丁不符、并发Writer/锁/Fence冲突、许可/范围不符、网络中断后结果不确定、部分写入未对账、数据库损坏、COMMIT失败、停止/清理失败、实际OAuth平台不支持静态client，均停对应阶段。
只停受影响阶段，其余独立只读/文档事项可继续；不通过更换命令/编号/账户/工具规避拒绝，不凭剩余次数盲试。

## 恢复检查点
1. 调用返回前失联/超时：查原operation/InvokeId及现场记录；未知不重发写入。
2. 下载/依赖安装失败：保留原stage/轮子/日志及失败返回；不删除、覆盖或换公开镜像。未完整逐SHA文件禁止安装/解包；已成功步骤不重做。
3. 配置/身份/权限不符：保留metadata和原值，停止启动。不得为过测关闭ProtectHome/ProtectSystem或放宽目录/文件。
4. DB部分初始化或状态未知：保留原DB、WAL/SHM与事务记录，停止；禁止rm/REPLACE/创建空库“恢复”，只能走已审显式恢复并核原历史。
5. 新authority启动失败：保留状态/配置/source/退出原因，仅停止这次拥有的新服务（须在原适用范围）；第一次部署没有旧3.12服务可恢复。后续已有旧服务才可按已记录的准确绑定并确认schema兼容后恢复。
6. 新域HTTPS/nonce观察失败：只按本事务记录恢复其拥有的配置绑定并测试/reload、核撤除；保留证据。未核实原配置或reload结果未知时不盲目写回，introspect保持deny。证书、ACME、旧站点/旧连接不动。
7. 新App/隧道/OAuth失败：停止新链；原受信连接保留；正常撤销/恢复动作只限明确授权的新对象，保留DB与日志，禁止复用已消费Attempt。
